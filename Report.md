## 8. Task 12: Vulnerability Assessment

### 8.1 Objective

The objective of this task was to use the information collected from Tasks 7–11 and prepare a basic vulnerability and security assessment.

The assessment focused on identifying security weaknesses, classifying their severity, providing evidence, and recommending appropriate security measures.

### 8.2 What is a Vulnerability?

A vulnerability is a weakness in a system that could create a security risk.

Examples of security weaknesses include:

- Unnecessary services running.
- Sensitive ports exposed.
- Outdated software.
- HTTPS not enabled.
- Directory listing enabled.
- Server/version information exposed.
- Weak security configuration.

### 8.3 Previous Results Reviewed

### 8.4 Security Weakness Identification

The following areas were checked:

Ports and Services
- Is the service actually required?
- Is a sensitive service exposed?
- Is an insecure protocol being used?

Software
- Is the software outdated?
- Is it still supported?
- Does the particular version have known security vulnerabilities?

Web Applications
- Is HTTPS enabled?
- Is directory listing enabled?
- Is sensitive information exposed?
- Is server/version information visible?

Configuration
- Are unnecessary services enabled?
- Is access unnecessarily exposed?
- Are security controls missing or incorrectly configured?

> ## 9. Task 13: Security Hardening & Before/After Testing

### 9.1 Objective

The objective of this task was to identify security weaknesses in the authorized lab environment, apply security hardening measures, and verify the improvement using before-and-after Nmap scans.

### 9.2 Security Hardening

Security hardening is the process of reducing the attack surface of a system.

The attack surface can increase because of:

- Running services.
- Open network ports.
- Installed software.
- Permissive configurations.

The hardening process follows:

Assess → Harden → Verify → Monitor → Reassess
